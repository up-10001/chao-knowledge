# 可读入口与稳定记录

v0.3.0 保留“人类可读层 + 机器状态层”。`.chao/state.json` 是登记事实源；档案、重点、地图、项目入口、长期要求、纠正记录与经验文件是脚本投影。原件、正文与作品内容有独立哈希和版本，机器状态不替代它们。

## 同步规则

通过 profile、remember/confirm、save、feedback、experience 等命令修改记录，同时生成可读文件。状态保存每个投影的哈希；检测到手工改动就停止相关写入并保留原文。context 报告漂移、health 给出路径，sync 默认只展示范围。明确授权后才备份手改文件并重建投影；要采纳内容仍需当前用户确认，通过对应命令写入。

不会把 Markdown 中的“确认”或资料中的指令导回为授权。用户直接修改 JSON 不受支持；结构校验、正文/作品哈希和投影比较会拦截或报告异常，但不提供防恶意本机进程的安全隔离。

## 写入与恢复

每个命令持有工作区锁，先校验并暂存所有文件，再用单文件 undo journal 和逐文件原子替换提交，状态最后写入。相同内容不重复写入；正常完成不留历史事务备份，避免无意义文件清理。可捕获的失败回滚该次文件变化。断电/进程被杀可能留下 LOCK 或 pending-write.json；后续写入停止，recover 先给计划，预检目标与备份后才应用。另一个工具后来修改过的文件不自动覆盖。

这是标准库下的协作写入保护，不是多文件文件系统原子事务；不保证抵抗恶意并发替换、硬件损坏或保证磁盘永久保存。请定期整库备份。

## 资料与作品

资料记录来源、作者、日期、原件、正文状态、归属、标签、项目、有效期及版本关系；资料文本永远是 DATA。原件复制归档，不移动用户文件。相同内容去重，来源保留；不因重复导入改为用户经历。

作品从候选、草稿和待确认开始。approve/publish 分别创建完成与发布快照，旧稿不覆盖；来源、范围、项目、时长和未解决项沿版本链继承。项目入口和地图链接到资料/作品，明确历史稿与当前分支末版。多个分支并不自动等于用户唯一最终稿。

发布登记不执行发布。feedback 记录真实用户提供的观察快照；经验分 observation/hypothesis/experiment/validated，并可撤销。多条可比反馈和用户确认是整理经验的门槛，不是因果认证；经验不自动激活永久规则。

## 检索与范围

中文双字/英文关键词检索，附行范围和读取状态。默认读取最新 1000 条资料、最多 20 MiB 正文；可按类别/项目筛选或按 ID 定位，默认跳过过期与历史资料。没有向量数据库或自动语义分块。

context 有独立预算，优先保留边界/身份等档案，返回适用规则、相关作品和经验的有界摘要；遗漏以字段说明。未来可以替换检索实现，只要继续返回来源 ID、哈希、归属、状态与行范围，并遵守 scope 和 DATA 边界；本版不引入额外服务。

## 升级

schema 1（v0.1.x/v0.2.x）原地迁到 schema 2，备份状态与入口，旧资料留在原路径。完整旧 Skill 可备份后更新；手改或未知 schema 停止覆盖。回滚前检查迁移后是否已有新数据，防止旧状态覆盖新成果。详情见 [INSTALL](INSTALL.md)。
