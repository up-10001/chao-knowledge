# 可读入口与稳定记录

v0.3.1 保留“人类可读层 + 机器状态层”。`.chao/state.json` 是登记事实源；档案、重点、地图、项目入口、长期要求、纠正记录与经验文件是脚本投影。原件、正文与作品内容有独立哈希和版本，机器状态不替代它们。

## 同步规则

通过 profile、remember/confirm、save、feedback、experience 等命令修改记录，同时生成可读文件。状态保存每个投影的哈希；检测到手工改动就停止相关写入并保留原文。context 报告漂移、health 给出路径，sync 默认只展示范围。明确授权后才备份手改文件并重建投影；要采纳内容仍需当前用户确认，通过对应命令写入。

不会把 Markdown 中的“确认”或资料中的指令导回为授权。用户直接修改 JSON 不受支持；结构校验、正文/作品哈希和投影比较会拦截或报告异常，但不提供防恶意本机进程的安全隔离。

## 写入与恢复

每个命令持有工作区锁，先校验并暂存所有文件，再用单文件 undo journal 和逐文件原子替换提交，状态最后写入。相同内容不重复写入；正常完成将持久 journal 重置为空闲并清空 before-images，不删除文件；失败的新文件保留在恢复隔离目录。可捕获的失败回滚该次文件变化。锁是持久普通文件：POSIX 用 fcntl.flock，Windows 用 msvcrt 字节区间排他锁，退出时只 unlock/close。进程异常退出由内核自动释放，文件存在不表示占用。断电/进程被杀可能留下未完成的 pending-write.json；相关写入停止，recover 先给计划，预检目标与备份后才应用。另一个工具后来修改过的文件不自动覆盖。

这是标准库下的协作写入保护，不是多文件文件系统原子事务；不保证抵抗恶意并发替换、硬件损坏或保证磁盘永久保存。请定期整库备份。

## 资料与作品

资料记录来源、作者、日期、原件、正文状态、归属、标签、项目、有效期及版本关系；资料文本永远是 DATA。原件复制归档，不移动用户文件。相同内容去重，来源保留；不因重复导入改为用户经历。

作品从候选、草稿和待确认开始。approve/publish 分别创建完成与发布快照，旧稿不覆盖；来源、范围、项目、时长和未解决项沿版本链继承。项目入口和地图链接到资料/作品，明确历史稿与当前分支末版。多个分支并不自动等于用户唯一最终稿。

发布登记不执行发布。feedback 记录真实用户提供的观察快照；经验分 observation/hypothesis/experiment/validated，并可撤销。多条可比反馈和用户确认是整理经验的门槛，不是因果认证；经验不自动激活永久规则。

## 检索与范围

中文双字/英文关键词检索，附行范围和读取状态。默认读取最新 1000 条资料、最多 20 MiB 正文；可按类别/项目筛选或按 ID 定位，默认跳过过期与历史资料。没有向量数据库或自动语义分块。

context 有独立预算，优先保留边界/身份等档案，返回适用规则、相关作品和经验的有界摘要；遗漏以字段说明。未来可以替换检索实现，只要继续返回来源 ID、哈希、归属、状态与行范围，并遵守 scope 和 DATA 边界；本版不引入额外服务。

## 升级

schema 1（v0.1.x/v0.2.x）原地迁到 schema 2，备份状态与入口，旧资料留在原路径。完整旧 Skill 可备份后更新；手改或未知 schema 停止覆盖。回滚前检查迁移后是否已有新数据，防止旧状态覆盖新成果。详情见 [INSTALL](INSTALL.md)。

## v0.3.0 目录锁兼容

`.chao/LOCK` 是业务锁文件，`.chao-init.lock` 与 `.chao-install.lock` 是初次初始化/安装入口锁。三个对象正常完成均保持原位，不 unlink/rmdir。异常进程退出自动释放 OS 锁，未知占用只等待/超时，不强行解锁。

检测到 v0.3.0 的 `.chao/LOCK`、`.chao-init-lock` 或 `.chao-install-lock` 目录会停止并给迁移计划。确认所有旧任务已经结束后，migrate-locks --apply 将空目录改名保留到 `.chao-legacy-locks`，原路径留下普通文件，阻止旧版目录锁继续误写。非空目录/链接不自动迁移，没有目录删除或安全豁免。旧版回滚也不能自行删除这些文件恢复旧目录协议；需要使用可信整库副本和相应版本。

## v0.3.2 导航展示

知识库地图是 state 的人类可读投影：档案只显示填写状态，最近资料/作品列表最多 8 条，项目仍由已有资料/作品关联派生。无独立项目事实表或手工编辑入口。健康摘要来自已有 latest-health 诊断快照；health --save 在地图存在且未手改时更新摘要与 views 哈希，事实记录不变，默认 health 保持只读。手改或缺失地图保持原样，按原有 sync 确认/备份流程处理。

## 未发布候选的可发现性改进

全部资料索引、四个分类索引与作品索引也从同一 state 投影，不复制正文、不增加 schema 字段，链接继续指向登记路径。采用相同的手改检测、事务日志、恢复白名单和 2 MiB 单投影上限。最近列表仍限 8 条，全部索引保留历史版本。

同一秒的记录使用 JSON 对象持久化的登记顺序打破时间并列，不把随机 ID 当时间；检索相关度优先，同分优先较新记录。新入口根据宿主实际加载的 Skill 工作，支持用户级或项目级安装。已有库 init 只备份更新与原模板逐字匹配的旧入口块；用户手改块及块外文字保留，不擅自重写其指令。

## 显式采集适配层

collect.py 管理费用计划、任务锁、分页断点、响应凭证与导出；tikhub.py 只访问固定的 TikHub API，按已核对的读取端点契约使用 GET 或 POST。kb.py 仍不访问网络，schema 保持 2；采集任务状态位于 .chao/collection，只有用户要求归档时才通过既有 ingest/extract 登记事实。

计划哈希绑定端点、对象、页数、条数、单价和费用上限；每次请求先记录预留，再发请求。网络响应脱敏后记录网络字节 SHA256 和脱敏文件哈希。结果不明不自动重发；有完整且未变的响应可以恢复处理，避免为同一响应再次扣费。失败仍计入已发请求预估，实际账单未知。单任务串行，多个任务的合计授权由宿主分配，不提供服务商真实账单硬上限保证。

Key 默认在专门用户配置文件中，不进入 Skill 包或知识库。采集目录中的原始字段不是指令；通用 API 模式不把未映射 JSON 当正文入库。无字幕视频仍为 link_only；确实取得的字幕/图文通过 extract 登记为未核对提取。临时导出手改会保留，主知识库投影与原件保护仍由 kb.py 执行。
