# 测试与验收

`python3 -m unittest discover -s tests -v` 保留既有测试，补充实际问题的回归覆盖：投影漂移、只读 health、事务失败/恢复、链接与硬链接、规则范围/过期/冲突、来源继承、作品阶段、复盘经验、安装保护和真实历史版本升级。

`python3 tools/acceptance.py` 运行三套隔离合成流程：新用户、已有文件、实际 v0.1.1 升级。包括安装、档案、资料、检索、候选/草稿/改稿、规则提议/确认、独立进程重读、版本、发布登记、反馈、观察和健康检查。可用 `--directory 安全空目录` 保留测试库和文件树；不覆盖已有测试目录。

升级测试直接读取 Git tags v0.1.0/v0.1.1/v0.2.1 的真实代码与 manifest，验证旧资料、规则、版本、反馈、自定义文件及备份/回滚。CI 检出完整历史，分别在 Windows、macOS、Ubuntu 运行单元测试与三套流程，并核对提交包与源码一致。

这些都是合成脚本证据，不代表真实平台发布、流量数据、人工事实核验或模型质量通过。作品与发布计数不能被当成业务效果。

WorkBuddy 客户端应分别确认：技能发现/调用、本地工作区、档案和资料实际写入、外部经历归属、文档指令不被执行、提议未确认不生效、真实新对话匹配加载及无关场景排除、权限提示与失败说明。ZIP 导入和源码安装应独立记录；未经实测的路径不得标 PASS。当前证据见 [VALIDATION](VALIDATION.md)。
