# 测试与验收边界

## 自动化测试

执行 `python3 tools/package.py` 后运行 `python3 -m unittest discover -s tests -v`。
测试对象是本地脚本、安装器与文件包；所有测试数据均为临时虚构数据，不能作为客户案例或实际业务成效。

覆盖的确定性行为：目录保护与重复初始化、现有配置保留、文件去重、来源与提取状态、中文/英文检索、读取预算/完整性、规则提议/确认/范围/替换/到期/撤销/移除、作品版本与人工验收标记、反馈分母/空值/时间窗口、安装包清单。

不覆盖：真实模型的理解和写作质量、宿主对所有指令的服从、真实平台链接的提取、音视频转写精度、作品表现或商业效果、所有安全漏洞。

## WorkBuddy 客户端人工验收（发布初始状态：NOT_RUN）

| 项目 | 初始状态 | 需要的证据 |
|---|---|---|
| 技能面板 ZIP 导入和发现 | NOT_RUN | 客户端版本、导入路径、技能面板 |
| 项目目录自动加载 | NOT_RUN | 新任务中的实际 Skill 调用记录 |
| 首次完整任务 | NOT_RUN | 真实资料到草稿与来源卡 |
| 新对话读取已确认规则 | NOT_RUN | 两个独立会话及规则 ID |
| 不匹配场景不调用规则 | NOT_RUN | 不同范围的 context 与成品 |
| 撤销后新对话不再使用 | NOT_RUN | 撤销记录及后续 context |
| 链接打不开不虚构转写 | NOT_RUN | 实际失败提示及降级路径 |

脚本单测里的“新进程重新读取状态”只证明磁盘持久化，不得写成“WorkBuddy 跨对话实测通过”。macOS 脚本通过也不等于 WorkBuddy GUI 通过。

## 人工结果记录格式

日期、WorkBuddy 版本、操作系统、模型、测试工作区、步骤、预期、实际、PASS/FAIL/NOT_RUN、脱敏证据位置。只有真实执行后才更新对应状态。公开报告不要上传个人资料或秘密。
