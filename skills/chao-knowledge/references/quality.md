# 成品验收与质量检查

## Agent 保存前检查

核对受众与任务类型，确认未把口播风格用于正式报告；核对引用的资料确实有可读正文，且摘录足以支撑相应主张。

逐项检查第一人称经历、客户、结果和收益的主体：用户自述、用户团队、同事、外部作者与虚构示例必须分清。没有本人依据时不写成“我”。对标内容仅提取可借鉴方法，不逐句洗稿。

当前工具功能、价格、政策和收益数据必须带实际核查来源与日期；不能联网时列为待核对。数据是观察还是推断要分开，不凭单条表现认定因果。

## 用户验收卡

正文之外，用几句话说明：用了哪些用户资料及来源位置；哪些信息尚待核实；哪些个人经历没有采用或被删去；现在存为哪一版草稿。由用户决定是否定稿。

**来源卡不是事实核验器，规则筛选不是模型服从保证，脚本单测不是 WorkBuddy 实测。**

## 跨会话验收

会话 A：在独立测试工作区保存一条有明确范围的要求，经用户确认后记下真实规则 ID。
会话 B：新建对话、选择同一工作区，以匹配范围的任务运行 context；确认该 ID 出现，再生成内容。
会话 C：换成不匹配任务，确认该规则不出现。
会话 D：撤销该规则，再开新对话确认不出现。不能用同一聊天窗口中的记忆代替这组测试。

## 人工测试记录

记录宿主名称/版本、操作系统、模型、工作区、测试日期、实际结果和脱敏证据位置。尚未执行的项目写 NOT_RUN，不默认 PASS。示例内容明确标“虚构示例”，禁止作流量、收入或客户背书。
