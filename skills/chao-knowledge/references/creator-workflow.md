# 自媒体工作流

这套流程用于内容创作，不要求用户一次维护所有文件。Agent 只在任务需要时读取对应资料。

## 资料路由

- `02-资料库/对标内容/`：公开作品、逐字稿、竞品、案例。保留平台、作者、链接/原件和日期。
- `02-资料库/用户反馈/`：评论、私信、问卷、常见问题。不要把单条评论当成总体用户画像。
- `02-资料库/行业资料/`：行业、产品、政策、课程和研究资料。时效信息使用前重新核验。
- `02-资料库/素材/`：其他可复用素材。

## 内容流转

`选题池 → 草稿 → 待确认 → 已完成 → 已发布与复盘`

1. 选题：结合当前目标、用户反馈和对标资料提出候选，不把对标标题直接换词。
2. 草稿：调用个人档案、适用规则和相关资料，外部经历保持归属。
3. 待确认：列出用户需要确认的第一人称经历、事实和时效信息。
4. 已完成：只有用户明确验收后才进入完成状态；完成不等于已经发布。
5. 已发布与复盘：保存真实数据窗口，区分事实、可能原因和下次实验。

## 对标内容的使用边界

允许借鉴主题、信息组织、开头方法、节奏和论证结构。不要逐句同义改写；不要把外部作者的客户、成绩、收入、公司经历或个人故事改成用户自己的第一人称事实。

如果需要说“我做过”“我的客户”“我们跑了多少播放”等，必须在用户档案或用户明确提供的材料里找到对应依据；团队/同事案例仍标注归属。

## 复盘进入经验库

单条数据只形成“待验证假设”。只有多次结果、口径可比，并且用户明确确认后，才可以写入 `05-经验与规则/已验证经验.md`。规则本身仍需通过 remember/confirm 机制生效。
